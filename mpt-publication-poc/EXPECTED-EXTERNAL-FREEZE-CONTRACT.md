## Responsibility and trust boundary

External Offline Admission Authority (OAA) is a proposed component outside the eight-file core.
Its independently administered policy identifies allowed human reviewers, public keys, role,
scope, algorithm, policy version, validity/revocation evidence and separation of duties.
SECURITY_REVIEWER owns policy/verification; INDEPENDENT_CODEC_REVIEWER owns byte review;
DOMAIN_CONTRACT_REVIEWER owns SNAP decisions; OFFLINE_ENVIRONMENT_OWNER owns loader/monitor;
CODEC_REVIEWER owns observer adapter. All people, products and implementation choices UNRESOLVED.
Do not choose a signature algorithm/vendor/dependency implicitly. No online trust lookup in the
offline run: an approved dated offline policy snapshot must establish freshness and revocation.

The comparator's authenticate callback is only a hook. It must be created by the trusted OAA
host from verified immutable approval bytes, not passed by an untrusted bundle/user script.
A true-returning callback or SHA equality alone never proves reviewer authority.
OAA must deny admission if signature, role, independence, scope, policy freshness or code loading
cannot be verified. No trust-on-first-use, unsigned fallback or simulated record accepted.

## Phase 3: COMPARE_FROZEN (distinct future execution authority)

OAA authenticates phase-2 decision and verifies separate execution authority/environment.
Comparison admission record additionally pins loaded comparator/observer/host and actual runtime.
Do not infer execution permission from a semantic freeze signature. Current six-source Python
binding omits these host/runtime identities: OAA must validate them before constructing that binding.

Proposed path policy: approved absolute local path under C:/mpt-offline-review/expected/,
filename reviewed-frozen.json; no relative/UNC/device/alternate-stream path, traversal, alias,
reparse/symlink redirection or unapproved writable/hardlink substitution. OS-specific validation
and identity strategy require approval. A string prefix check or resolve-then-reopen is insufficient.
Open under a protected read-only directory and retain one stable handle; record filesystem object
identity and length, bound before allocation, read exact bytes once from that handle and hash them.
Verify signature-bound bytes and retained identity, and pass that immutable byte buffer to Python.
Reject replacement/truncation/identity change; don't hash one file and read another.
No environment or CLI path override after admission.

Measure loaded executable/module/stdlib artifacts from the protected import location. Disable
unapproved search paths/cache/import hooks; refuse unmeasured bytecode/native extensions.
The chosen OS loader strategy must demonstrate that measured bytes are the bytes actually loaded,
not merely a matching __file__ or claimed hash. This proof is currently missing (SR15-01).
Bind immutable host admission evidence to exact signed decision; never let observed results
populate source identities or expected fields.

Call validate_frozen before granting observer access. A future separately approved adapter maps
SUT outputs to the 428 exact IDs without calculating new expected data. Expected bytes are held
in immutable input; observed evidence goes to a disjoint bounded output directory.
After comparison recheck retained file identity/hash and protected input inventory; reject mutation,
preserve both streams and divergences. Do not truncate differences into a successful result.
Runtime limit/observer exception must produce explicit failure evidence, not a comparison verdict.
No automatic approval, gate promotion or rewrite of expected artifacts.
